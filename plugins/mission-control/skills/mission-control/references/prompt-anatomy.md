# Prompt anatomy — the forge grammar

Every deep prompt is assembled from an **invariant skeleton** + **fresh-recon variables** + **situational modules**, and ships beside a **launch block** — the operator-facing pre-flight that carries everything the prompt itself must not. §0 states what a forged prompt never contains; the skeleton is never skipped; modules are selected by the package's nature; variables are always verified the same turn they are written. The consumer half lives in the pasted prompt; the operator half lives in the launch block.

## §0 — Negative scope: what a forged prompt never contains

A forged regenloop-lane prompt contains ONLY:
- the invocation line: `/regenloop-run <mode> <safe> <ship> --slug <slug> <goal in one sentence>` — `<mode>` = `--deep` (default) | `--short`; `<safe>` = `--safe` unless the operator declined; `<ship>` = `--ship|--no-ship` per the launch-block host policy (field 6);
- the positioning command (fenced, with the cwd it runs from);
- program facts — the things only the controller knows: frozen contracts, scope fences and owned files, baseline evidence pasted verbatim, kill switches, expected artifacts;
- the records contract (where this session's evidence lands, and where it must not);
- human gates (pause points);
- a wall-clock bound.

And NOTHING that restates regenloop mechanics: no base-capture semantics, no goal/stall/clarify behavior, no caps arithmetic, no ship internals, no host prose unchecked against `git remote -v`.

Principle: the session has the manual loaded — the regenloop skill sits in its context, current version, and outranks whatever this prompt remembers. Mechanics in a forged prompt are at best noise and, when reality drifts from the controller's memory of the manual, a live round: the program's three worst prompt moments (the equality STOP that fired on a legitimate merge, the goal-guard folklore, the GitLab ship promise on a GitHub repo) were all mechanics the session's own manual contradicted or outranked. If the operator needs the fact, it goes in the launch block; if the session needs it, the loaded manual already has it; if neither, delete it.

Deleted outright by §0 (all were present in the program's real prompts): goal guards (folklore — "two active goals stall" was unsupported; routing is the `--slug` join plus controller-side provenance at verify), "read the recorded base_sha back" (base-capture semantics), "tests capped per --safe" as prompt prose (caps arithmetic), "no GitLab writes beyond the ship PR" (host prose), "3 consecutive gate-red rounds" (retry arithmetic), Clarify causal models, and any stall/ship behavior restatement.

## The skeleton (always, in this order)

1. **Invocation + goal.** For regenloop lanes: `/regenloop-run <mode> <safe> <ship> --slug <slug> <goal in one sentence>` — `<mode>` = `--deep` (default) | `--short`; `<safe>` = `--safe` unless the operator declined; `<ship>` = `--ship|--no-ship` per the launch block's host policy (field 6). The slug is the join key between the program-note row, the goal dir, the branch, the reports, and the archive row — pass `--slug` explicitly; never "suggest" it in prose. For plain-deep lanes: "You are an implementation agent…" with the same discipline hand-written.
2. **Declared authority.** One line, early: "Operator /goal overlays supersede this prompt where they conflict; the skill's own defaults govern where both are silent. Record every overlay you act on as a `decision:` entry. The never-merge boundary holds regardless of any overlay." Overlays arrive seconds after the paste and both resolve precedence the same way — codify it, don't leave the recording duty to be invented mid-run.
3. **Unattended rules (or attended rules).** Never block on a question; the wall-clock bound (item 11) governs. NO caps content here: caps have one home — the launch block's caps + T line (field 5). The prompt may state "tests capped at N via the launch-block export" and nothing else; never a bare number, never an env name, never arithmetic. Attended variant: explicit evidence checkpoints instead of a time bound.
4. **Base verification, immediately after kickoff.** The exact SHA with its verification timestamp, and the baseline evidence lines pasted verbatim — journal output, API results, the incident lines that motivated the work; never summaries: proof that exists only in the controller's scrollback is invisible. The fenced positioning command with its cwd (`cd <repo> && git fetch origin && git checkout --detach <sha>`), or a behavioral precondition ("origin/main must CONTAIN <the merge that matters>"). Include the repo-specific base rule from the facts note. Pin-expiry clause: "pin verified <datetime>; a pin older than 4 hours, or older than the last merge event on the base branch, is stale by default — it is re-derived at forge, and the launch-block recheck is mandatory before pasting." Mismatch tiering — the prompt's ONLY base rules:
   - record the actual base loudly (`decision:` entry + provenance in the MR/PR body); never silently self-correct;
   - actual descends from the pin (`git merge-base --is-ancestor <pinned> <actual>`) AND `git diff --name-only <pinned>..<actual>` ∩ owned-files = ∅ → adopt loudly, record, proceed;
   - non-ancestor (history rewrite/reset) or owned-file intersection in the delta → full cleanup, STOP.
   Positioning rule: NEVER an equality pin combined with detach-at-moving-`origin/main` — the prompt's own launch recipe must not be able to contradict its base pin. NOTHING about how the run captures or persists its base — that is the run's own machinery.
5. **Fence self-containment.** Every command, path, and cwd the session must run — repo resolution, positioning, and the READ FIRST block (program-note permalink, the package's brief section, the design sections it cites, nothing else; anything more wastes the session's context) — is inside the fenced paste block. The controller's surrounding prose is invisible to the session. Before emitting, simulate the first three tool calls of a fresh session using only the fence: repo resolution, positioning, and READ FIRST must all resolve.
6. **Scope in / scope out + owned files.** What the session must not touch — including the other lanes' repos. Owned-files lists make cross-session conflict checks mechanical. When scope touches a shared artifact, enumerate ALL its consumers in the READ FIRST block and fence each — the artifact's self-declared debt is not a blast-radius map.
7. **Engineering rules.** The repo's exact gate/test command read from gates.toml/facts note; TDD two-commit receipts (red, then green) with a fixture prefix unique to this session; plain `git commit -m`, default identity, no `-c` flags, no attribution; decisive evidence lines into the MR/PR body. No restatement of regenloop procedure.
8. **Clarify pre-answers — autonomy/ship/safe/scope only.** The Clarify batch pre-answered in the prompt and recorded by the session as `decision:`/`assumption:` entries: autonomy=unattended (the load-bearing pre-answer); ship per the launch block's host policy; safe per the invocation's `--safe`; scope = below only. There is no Clarify question about caps — caps never appear here (item 3).
9. **Records contract.** Regenloop lanes: handoff (branch, MR/PR number, base sha) in the MR/PR body + goal state; vault note appends are the controller's job. Plain lanes: one attributed section in the program note. Name the negative space — what the session must NOT write.
10. **Expected artifacts + trigger mechanics.** Expected artifacts as falsifiable EXPECT lists with pre-committed abort rules written before the happy path. Any EXPECT about system behavior — what fires a sweep, where an emit lands, which bot listens, what a deployed consumer does with this lane's output — cites the deployed code line that implements the trigger, verified this turn, exactly as a SHA must exist right now. Every wait carries an else-branch ("if nothing by T, conclude absent and self-verify, recording the substitution"); never promise a reviewer or bot the platform cannot deliver.
11. **Stall rule — wall-clock only.** "Past <T> hours → bring the current task to a cleanly-reported state, run the full cleanup protocol, STOP. Never thrash, never improvise around a guard refusal; a `could_not_run` halt is surfaced, not coded around." NO retry counts, NO gate-red arithmetic — the envelope already governs retries; a forged retry rule competes with the machinery. T is derived at forge, never guessed: T = round-up-to-next-hour( 2 × (queue-task count × the repo's suite wall-clock, from the last machine report or the facts note) + gate count × the CNR re-probe allowance per `references/regenloop-interface.md` §6 ). Expected suite runs = the task count in the package's planned queue rows (one suite cycle per task). If any input cannot be read this turn, T is omitted and the launch block states "T unset — operator wall-clock watch". The launch block states T and this derivation line.
12. **Pause points (human gates).** "When Ready and green, PAUSE — surface the MR/PR for human merge; STOP cleanly if the operator is absent." MR vs PR per the launch block's host fact. One classified guard beats three absolute STOPs: a STOP-grade rule with no benign-delta path trains rule-breaking.
13. **Kill switches** (if production-adjacent): named, one line, "kill switch first, always." Program facts, not tool mechanics — they stay.
14. **Ship step per lane policy.** The invocation's `--ship|--no-ship` matches the launch block's host policy (field 6), decided from `git remote -v` this turn: `--ship` on a GitLab remote hands off to the ship flow (merge-ready MR, human merges); `--no-ship` on GitHub ends at a pushed branch + the explicit human/`gh` PR path. The never-merge boundary holds regardless (items 2 and 12); no host prose unchecked against the remote.

## The launch block

The companion that lives OUTSIDE the pasted prompt, shown to the operator alongside it. This is the pressure valve that makes §0 lossless: everything §0 ejects that someone still needs lands here, operator-facing. The launch block is never pasted into the session; it is the operator's pre-flight and the controller's own record of the envelope decisions the prompt no longer carries. This is the ONE home for these fields — SKILL §3 points here and does not re-enumerate them.

**Session type + envelope pin** — regenloop / plain-deep / box-plain; regenloop `<ver>` (the version verified at plan, interface doc §10); the goal statement reminds the operator the session must be fresh, so its loaded plugin is the pinned one; any version mismatch surfaced at kickoff stops the lane.
**Where to run** — repo path + "a fresh session" (the fenced prompt repeats the repo path and cwd itself; this field steers the operator, skeleton item 5 steers the session). Box-plain lanes add their ssh/key refs for the box.
**Positioning command** — the exact command, identical to the fenced one in skeleton item 4.
**Operator base-recheck line** — "before pasting: `git fetch && git rev-parse origin/main` — if ≠ `<sha>`, tell the controller before launching." Plus the pin's verification timestamp; a pin older than 4 h or crossing any merge event is stale by default: re-derive at forge, re-check at launch — forge-time verification expires at launch, and the gate's promise ("the operator should never find a stale SHA") is kept at the cheapest moment or not at all. The operator pastes the recheck output back to the controller; the prompt-log row's session-artifacts cell records it — verify flags any `launched` row with no recheck evidence.
**Caps + wall-clock T line** — one slot for both machine-derived envelope numbers, each with evidence or the sanctioned "unset" fallback. Caps: exactly one of two sanctioned forms, never both, never neither — (a) default: "no per-lane export; `--safe` caps at the machine guard ceiling (M workers, `regenloop_guard.py plan --json`, run <date>)"; or (b) pinned: export the current names only (`REGENLOOP_PYTEST_JOBS=N`, plus `REGENLOOP_SAFE_GATE_JOBS=K` where gates parallelize). T: the wall-clock bound with its derivation line (skeleton item 11), or "T unset — operator wall-clock watch". The evidence line for red-team check 6 is this field's `plan --json` output.
**Host/ship policy** — decided from `git remote -v` this turn. GitLab remote: `--ship`. GitHub remote: `--no-ship` + an explicit human/`gh` PR path (the ship handoff requires `glab auth` + a GitLab remote; on GitHub it degrades to surfacing a bare push — an unreviewed branch, no PR). Record which bots actually listen on that host; never write host-specific prose without the remote check.
**Operator launch gate** — the precondition that must hold before pasting ("only after goal X closes", "only after MR !N merges"). Operator: paste any `/goal` overlay you add into the controller chat as well — overlays supersede the prompt; verify judges the overlay-adjusted prompt.
**Goal statement** — the one-line essence printed above the prompt so the operator can sanity-check intent before pasting (the v1.2.0 standalone "Goal statements" section is dropped; this field is its one home): *"Make throttling fair, visible, and overridable: … — deployed and proven live."*

## Situational modules

| Module | Attach when | Contents |
|---|---|---|
| **Part 1 / Part 2** | Anything crossing a merge or deploy boundary | Part 1 = code + ship + merge-pause. Part 2 = patch/enable/verify, re-invocable as "Part 2 only"; its first lines verify the merge landed (ancestry check) |
| **Deploy window** | Part 2 touches a box/service | Pin (fresh pinned worktree — never the ambient checkout) → backup (timestamped) → swap → verify (sha/size N/N + 0 extras) → checkpoints before restarts → restart → healthz + clean journal → resume. Interim-behavior seam: when a lane's output is consumed by a system deployed or loaded elsewhere, forge-time must answer what the deployed consumer does with this lane's output between now and the consumer wave — that answer is the go/no-go; enumerate ALL consumers of the swapped surface and fence each |
| **Dogfood / canary** | Behavior must be proven live | Scratch MR, closed-unmerged; expected artifacts named with note ids; latency expectations (a 1-second "sweep" means it skipped — investigate); skip-path and dedup checks; "never merge". Same interim-behavior seam + consumer enumeration as the Deploy window row: what does the deployed consumer do with this lane's output between now and the consumer wave? That answer is the go/no-go |
| **Abort path** | Anything that can misbehave in production | Pre-committed: "any anomaly → <kill switch> → restart → STOP → full report." Two real production bugs were caught cheaply exactly this way |
| **Release prep** | A version bump must ship | Bump commit appended to the feature branch as the final isolated commit (the never-merges guard makes direct-main commits impossible anyway); release notes drafted; everything-but-the-click prepared for the operator |
| **Remediation** | verify found gaps | Gap-scoped only; opens with the labeled WHAT-WAS-CLAIMED-VS-FOUND preamble ("what was claimed vs what verify found") as the canonical form; same skeleton; explicitly bounds the session away from refactoring green work |
| **One-shot** | Triage says single session | The light form: setup verification (HEAD == expected SHA else the item-4 tiered mismatch policy) → branch name → 3–6 line scope → caps line (launch-block field 5) → plain-commit rule → ship step → stall rule. No program machinery |

## The red-team gate (before emitting any prompt)

This gate is the single red-team checklist — SKILL §3 points here and does not restate it. The ten checks, run before emitting any prompt:

1. **Exists now** — every SHA / flag / path / knob name exists right now, verified this turn — and the launch block carries the operator recheck line: forge-time verification expires at launch.
2. **Owned-file collision** — any collision with an in-flight session?
3. **Human-only work** — anything human-only disguised as agent work?
4. **Stall fires cleanly** — does the stall rule fire cleanly on the worst plausible failure — and is every STOP graded (benign-delta path vs true tamper) rather than absolute? One classified guard beats three absolute STOPs.
5. **Part 2 precondition** — does Part 2's precondition match what Part 1 actually produces?
6. **Caps fit** — do the caps fit the machine as it stands, citing `regenloop_guard.py plan --json` output (regenloop lanes) or the fresh headroom measurement (plain lanes) as its evidence line?
7. **Behavioral expectation** — every behavioral EXPECT — trigger conditions, parser acceptance, consumer reactions, emit locations, which bot listens — cites the deployed code line that implements it, verified this turn, exactly as a SHA must exist right now.
8. **Negative scope** — does any line of this prompt explain regenloop internals — base capture, goal/clarify/stall behavior, caps arithmetic, ship mechanics? Delete it. If the operator needs it, it belongs in the launch block; if the session needs it, the loaded manual already has it.
9. **Pin freshness** — does every pinned fact carry its verification timestamp, and is any pin older than 4 h — or older than the last merge event on the base branch — re-derived at forge and re-checked via the launch block? A pin with no timestamp fails this check.
10. **Authority declared** — does the prompt state where it stands relative to operator /goal overlays (precedence + the `decision:` recording duty), and do its pause points match the tool's own never-merge enforcement without renaming it?

A prompt that fails any check is reforged. The operator should never be the one to find a stale SHA — and the session should never be the one to discover the prompt was wrong about itself. Print the red-team record with every forge: one line per check with its evidence — the checklist form, never a narrative "all variables pinned" summary.
